# postsmith contracts (authoritative for every tool, agent and skill)

All tools: `uv run tools/<name>.py [args] [--json]`, run from the project root. Import shared helpers from `tools/common.py`. Exit code 0 with a JSON `{"ok": false, "error": "..."}` on bad input (never a traceback for user errors); exit 2 only for programmer errors. Every tool has `--help`. Paths in JSON are project-relative. Timestamps are ISO-8601 UTC. Ids are stable slugs. Nothing under `corpus/` is ever edited by a tool after ingest except adding cards/features.

Config: `config/postsmith.yaml` via `common.load_config()`. Rubric version: `evals/rubric/current` symlink → `evals/rubric/vN/`; `common.rubric_dir()` resolves it. Thresholds: `evals/rubric/vN/thresholds.yaml`. Patterns: `evals/rubric/vN/patterns.yaml`. Lexicon: `style/lexicon.yaml` (machine source of truth; `style/lexicon.md` is an optional rendered view).

## 1. Corpus post file `corpus/{posts,heldout,self}/<post_id>.md`
Front matter (YAML) then the verbatim text (line breaks preserved, one trailing newline). No rating field ever.
```yaml
schema: postsmith.post/1
post_id: acosta_017            # <author_slug>_<nnn>; self posts self_<nnn>
author: {name: "Lara Acosta", slug: lara-acosta, handle: "@laraacosta"}
platform: linkedin             # linkedin | x
posted_at: 2026-05-01          # or null
url: null
lang: en
source: {kind: csv|gsheet|md|json, ref: "...", file: "corpus/inbox/done/...", ingested_at: "..."}
content_sha256: "..."          # sha256 of common.normalize_text(text)
split: train                   # train | heldout | self (mirrors directory; sticky)
crosspost_of: null
variant_of: null
engagement: {likes: null, comments: null, reposts: null, views: null}
media: [{kind: image|video|carousel|screenshot|unavailable, path, preview, sha256, width, height, duration_s, frames_dir, transcript, provided_description}]
text_stats: {chars, words, lines, blank_lines}
```
`corpus/manifest.jsonl` rows: `{content_sha256, author_slug, post_id, split, source, ingested_at, crosspost_of, variant_of}`.

## 2. Card `corpus/cards/<post_id>.md` (heldout cards: `corpus/heldout/cards/`)
Front matter fields: `schema: postsmith.card/1, post_id, annotated_by, verified (bool), profile_version_at_annotation, thesis, subtext, archetype, angle (angles.md slug), emotion, hook {text, types[], above_fold_chars, standalone}, rehook, beats [{lines, beat}], expectation_ledger [{lines, sets_up, breaks_with}], rhythm, devices [{device, lines, note}], moves [], stance {earnest_ironic, humble_brash, warm_cold, dense_airy, abstract_specific} (0..1), pov, tense, address, ending, media_analysis {literal, on_media_text[], genre, role, caption_dependency, style_notes, reproducibility, what_it_adds, video}, why_it_works, what_would_break_it, distinctive_phrases[], generic_risk, humor_attempted, engagement`. Body: optional prose notes. `card_lint.py` checks: YAML valid; every `lines` citation exists in the post; device/archetype/hook-type/angle ids exist in `style/taxonomies/*.md`; for heldout posts, no quoted field (`hook.text`, `rehook`, `distinctive_phrases[]`, `on_media_text[]`) exceeds 6 words.

## 4. Candidate `drafts/<run>/round<k>/candidates/<cid>.md`
Front matter then the post text exactly as it would be pasted.
```yaml
schema: postsmith.candidate/1
cid: r1-w2-li                    # round-writer-platform (li | x | x1 for a one-liner)
platform: linkedin
writer: post-writer-2
round: 1
assignment: {angle_family: receipt, archetype: announcement_with_twist, move: corporate_register_for_trivial_event, device: anti_climax, lens: lara-acosta|null, seed: 4171, short_deadpan: false}
angle_sheet: {candidates: [{angle: "...", family: receipt, scores: {surprise: 4, truth: 5, specificity: 4, personal_fit: 5, timeliness: 3, disagreeability: 4}, killed_by: null}], pick: "...", runner_up: "...", emotion: OHHH, hook_family: story_in_medias_res}
hook_type: deadpan_announcement
ending: punchline
claims: [{text: "...", source: "persona.can_claim#4" | "brief.fact#2" | "brief.user_detail" | "opinion" | "joke"}]
media_intent: {decision: none|image|video|real_capture_direction, delete_test: "...", genre: null, concept: null}
lineage: {exemplars_seen: [acosta_003], lessons_used: [L-023], rewrite_of: null}
```
`tier0.py` writes `candidates/<cid>.txt` = post text only (no front matter). **Judges only ever receive the .txt inside a generated prompt file.** The cid is the file stem (`run_next` passes `--cid <stem>`); a front-matter `cid` that differs is a P0_schema hard fail, never a different output name. `claims` rows are validated by P0_schema: `text` a non-empty string of at most 300 characters, `source` exactly one of `persona.<section>#<n>`, `brief.fact#N`, `brief.user_detail`, `opinion`, `joke`; anything else (a note to the judge in the source field, an extra key) is a hard fail quoting the offending value.

## 5. Tier 0 output `drafts/<run>/round<k>/scores/<cid>.tier0.json`
```
{"schema":"postsmith.tier0/1","run":"...","cid":"...","round":1,"platform":"linkedin","candidate_sha":"...",
 "text_path":"drafts/<run>/round1/candidates/<cid>.txt","chars":1420,"x_len":null,"fold_preview":"...",
 "checks":{"P1_length":{"class":"hard","pass":true,"value":1420,"limit":3000,"evidence":[],"downgraded":false},
           "O1_ngram":{"class":"flag","pass":true,"hits":[{"ref":"welsh_004","span":"...","n":6}]}, ...},
 "advisory":{"fk_grade":6.1,"li_length_band":"in","first_line_words":6,"question_opener":false,"reading_time_s":40},
 "envelope":{"scope":"author:lara-acosta","score":0.81,"out":[{"feature":"sent_words.cv","value":0.31,"envelope":[0.48,0.9]}]},
 "small_corpus_mode":false}
```
Check ids (fixed): P0_schema P1_length P2_fold P_min_words P3_hashtags P4_links P5_markup P6_emoji P7_bait P8_opener P9_residue P10_contrast_flip P11_cluster P12_closer P13_specifics P14_dashes P15_burstiness P16_broetry P17_lists P18_hedges P19_clickbait P20_misc O1_ngram O2_phrases O3_skeleton O4_sibling O5_published E1_envelope. `class` ∈ hard|soft|flag|advisory (after base-rate downgrade; original class in `class_original` when downgraded). Every failing check carries `evidence: [{"span": "...", "why": "..."}]` with verbatim spans (one row per verbatim hit: each hashtag, each line with a curly quote). A check may pass its gate and still raise a flag (`{"class": "flag", "pass": true, "flag": true}`, P2_fold's word-boundary cut): `common.check_needs_action` is true for it, it counts in `n_flags` and it gates in `aggregate` like any flag. P0_schema also fails when the front matter does not parse (`missing: ["front matter", ...]`, `yaml_error`), when the declared cid differs from the file stem, and when a claims row is malformed (`invalid: [{field, value, why}]`); the tier0 JSON is written in every one of these cases. `x_len` counts as twitter-text does: URL 23 (trailing punctuation outside the URL), one emoji sequence (flag pairs, keycaps, skin tones, ZWJ sequences) 2, code points outside U+0000–10FF / 2000–200D / 2010–201F / 2032–2037 (CJK, but also `…` `•` `→` `€`) 2, everything else 1. `small_corpus_mode` (config `corpus`, counted over the train split only, the same rule as `status.py`) widens the envelopes to `envelope.small_corpus_iqr_widen` (default 1.5) and makes E1_envelope / P14 / P15 / P16 advisory (`class_original` recorded); a lens scope with fewer than `envelope.min_scope_n` (default 4) posts is advisory for the same reason. P8/P10/P12/P17 results carry `jury_override_allowed` (true only for a pattern hit that declares a known false positive; false for lexicon-only or heuristic-only hits, which go to the feedback packet instead of a jury).

## 6. Judge output `drafts/<run>/round<k>/scores/<cid>.<lens>.json` (written by the judge agent)
```
{"schema":"postsmith.judge/1","rubric_version":"v1","lens":"reader|voice|comedy|persona|media|lineup|pairwise",
 "candidate_sha":"...","dimensions":{
   "clarity":{"score":4,"na":false,"threshold":4,"pre_step":"...","evidence":[{"quote":"...","why":"..."}],
              "violations":[],"suggested_fix":null,"needs_confirmation":[]}}}
```
Dimension ids: reader → clarity, substance, hook, regret_risk, reply_worthiness. voice → register_match_self, level_and_move, not_ai, platform_register. comedy → humor, uniqueness, emotion. persona → persona_fit, claims (claims uses `claims: [{text, status, source}]` instead of score). media → media (sub-results alt_text_alone, does_work, slop_screen, executable, factual, capture_direction). lineup → `{"pick":"A|B|C|D","confidence":1-5,"tell":"...","quote":"..."}`. pairwise → `{"better":1|2,"better_evidence":"...","voice":1|2,"voice_evidence":"...","same_post_rewritten":null|true|false,"same_skeleton_or_joke":null|true|false,"evidence":"..."}`.

`judge_io.py validate <judge.json> --candidate <cid>.txt` → `{"ok": true|false, "rejected": [...reasons], "normalized": true}`. Evidence match: both sides NFKC, quotes/dashes/ellipsis folded, whitespace collapsed, case-insensitive; accept exact substring or difflib ratio ≥ config `evidence_fuzzy_ratio` against the best-aligned window. A dimension with `na: true` needs no evidence but does need a non-empty `pre_step` reason (rejected otherwise). A full judgement (not a `jury` or `rerun_for` file) must carry every dimension of its lens: a missing one is rejected per dimension (`dimension missing from judge output`) so the rerun ladder engages instead of the merge waiting forever; a rerun file that drops a dimension it was asked for counts as the second rejection. Lineup and pairwise files echo the `nonce` their prompt carried (`lineup.py score` / `pairwise.py score` discard a file without the matching nonce). Claim verification (`verify: true`) writes a JSON array `[{text, status, source, url, why}]` to `tier2/claims_<cid>.json`, not a judge document. The file name is authoritative for the lens (`<cid>.<lens>.json`, `<cid>.<lens>.rerun-<orig>.json`, `<cid>.jury.<lens>.<dim>.json`): a body whose `lens` disagrees is rejected whole.

## 7. Merged scores `drafts/<run>/round<k>/scores/<cid>.merged.json` (only `aggregate.py` writes this)
```
{"schema":"postsmith.scores/2","run","cid","round","platform","rubric_version","rubric_sha","profile_version","lexicon_version","candidate_sha",
 "tier0":{<check_id>:{class,pass,...}},
 "tier1":{<dim>:{"judge":"judge-reader","class":"hard|soft|advisory","threshold":4,"score":5,"na":false,"evidence":[...],"suggested_fix":null,
                 "jury":{"votes":[3,4,4],"median":4,"lenses":[...]}|null,"result":"pass|fail|na|hold|unscored","needs_confirmation":[]}},
 "tier2":{"lineup":{...,"pass":true}|null,"paraphrase":{...}|null,"pairwise":{...}|null,"claims":[...]|null,"media":{...}|null},
 "judge_io":{"rejected":[...],"na_by_rejection":[...],"na_declared":[...],"holds":[...],"contamination":[{"file","reason"}]},
 "verdict":{"status":"pass|fail|hold|needs_your_call|passed_tier1_only","hard_fails":[],"soft_fails":[],"flags":[],"unscored":[],"advisory":{},"na_declared":[]},
 "jury_requests":[{"dimension":"not_ai","reason":"threshold-1","lenses":["comedy","reader"]}],
 "stop":null|{"reason":"oscillation|regression|overlap_persistent","detail":"..."}}
```
Rules in `aggregate.py`: a hard Tier 0 fail is terminal. `run_next` requests no judge for such a candidate, so a merge with a hard Tier 0 fail and no judge file on disk leaves `tier1` empty, lists nothing in `waiting_on` and returns `fail` (the feedback packet comes from the Tier 0 spans); pass = all hard pass ∧ all soft ≥ threshold after jury ∧ no unaddressed flags (unless waived via `--waive`; a flag raised on a passing gate counts) ∧ (tier2 ran → lineup pass ∧ paraphrase false ∧ no wrong claim ∧ media pass). Jury trigger: soft score == threshold−1; hard judged score == 3; any hold; known-false-positive regex hit (P8/P10/P12/P17) only when the check carries `jury_override_allowed: true` (a lexicon-only or heuristic-only hit is a plain fail / flag for the feedback packet); O3 flag. `na` never fails; hard-gate `na` after rerun → hold → jury → unscored → needs_your_call. A judge-declared `na` on a dimension without an `na_when` / `na_allowed` rule (and not in `tier0.expected_na` or waived) is recorded in `na_declared` and counts toward `config.judges.max_na_by_rejection_before_needs_call` together with `na_by_rejection` → needs_your_call. The lens → dimensions map is `thresholds.lenses`, else derived from `dimensions[*].lens`; a rubric with no judged dimensions is a user error, never a pass. Judge and jury files that no `run_next` action requested (`state.json.requested_outputs`) are ignored and listed under `judge_io.contamination`. Base-rate downgrade only for `config.base_rate_downgrade.applies_to` when `profile.base_rates[check] > threshold`; never for `never` list. Oscillation: same dimension fails in rounds k and k+1 with contradictory suggested_fix (judged by keyword opposition or explicit `contradicts` field) or a hard gate that passed in k fails in k+1 → `stop.reason = oscillation`; a gate whose jury is still out in k+1 is not yet a fail, and a pass granted by a jury override in k is not a pass a rewrite can regress from. Regression: a fix breaks a previously passing hard gate twice → drop. O1/O5 flag surviving two rewrites → drop. `aggregate.py feedback <cid>` writes `round<k>/feedback/<cid>.md` + `.json` containing only failing/flagged checks with evidence, suggested fixes, out-of-envelope numbers, lineup tells.

## 8. Run state `drafts/<run>/state.json` and `run_next.py`
`run_next.py <run>` reads the run directory (never any label store) and emits the next batch:
```
{"run":"...","round":1,"stage":"write|tier0|tier1|aggregate|jury|feedback|tier2|deliver|done|stopped",
 "actions":[{"kind":"agent|tool","agent":"judge-reader","prompt_file":"drafts/<run>/round1/prompts/<cid>.reader.md","output_path":"drafts/<run>/round1/scores/<cid>.reader.json","cid":"..."}],
 "waiting_on":[], "notes":["..."]}
```
Stage derivation: candidates present without tier0 → tier0 (`tier0.py <md> --cid <stem> [--siblings ...]`; a cid whose tier0 action was already emitted for an unchanged candidate file goes to `waiting_on` instead of being re-emitted); tier0 without judge files → tier1 (emit one action per judge lens per candidate that passed hard checks); judge files present without merged → aggregate; outstanding reruns and juries are emitted before any `stop` is honoured; merged with jury_requests unmet → jury; failing candidates without feedback → feedback; feedback present without next-round candidate → write (rewrite); passing candidates → tier2 for top finalist per platform; tier2 complete → deliver, whose tool actions are, in order, `quote_leak_check.py <finalist.txt>` per finalist, `assemble_report.py <run>` and `topics.py add <run> --outcome pass` (`--outcome` omitted when no candidate passed; the topics action needs the topic `run_next.py init` recorded in `state.json` / `matrix.json`, a hand-assembled run gets a note instead), each `depends_on` the previous; `final/report.md` present → done, unless `final/.stale` exists (written by `--media`, JSON `{schema: postsmith.stale/1, reason, cid, ts}`), in which case `assemble_report.py <run>` is emitted again (stage deliver) and `assemble_report` removes the marker. When config `run.quick_lineup_on_tier1_pass` is true (default false), a one-judge quick lineup rides along with whatever stage is current for every candidate whose merged says pass: `lineup.py build` with the Tier 2 seed (same key and token), one `judge-lineup` on a lens chosen by a stable hash of the cid, `lineup.py score` (one pick → `flag`); the flag ranks like a soft fail in the finalist choice and is never a gate; the finalist's Tier 2 lineup reuses the build, adds the two remaining lenses and re-scores when a pick is newer than the score file. Prompt files for judges are generated by `run_next.py` under `round<k>/prompts/` (self-contained: rubric §0 protocol pointer, dimension list, candidate text in `<untrusted_post>`, platform, char count, exemplar letters where needed, output path; every wrapper tag inside untrusted text is escaped by `common.escape_untrusted`). The voice prompt states `lens: <slug>` or `lens: none` (the lens-free writer, the only case where `level_and_move` is na) and inlines the assigned move's `style/moves.md` entry inside `<move_entry>` (mechanism, trigger, shape, execute_without_copying, risk, platforms; never `seen_in`, post ids scrubbed; a move without an entry gets a note to score from the reference posts and write `move entry not supplied` in `pre_step`). The persona prompt inlines `<persona_excerpt>` (front-matter `can_claim` / `cannot_claim` / `do_not_target` numbered plus the story bank, opinions held and refused, vocabulary, claims and never sections of `style/persona.md`), `<brief_facts>` (the brief's `brief.fact#N` lines and `brief.user_detail`) and the writer's claims as escaped JSON rows inside `<untrusted_claims>`; it never names a file under `style/`. Writer prompts live under `round<k>/writers/` (`writer-<n>.<token>.md`; `rewrite-<cid>.<token>.md` inlines the feedback packet inside `<feedback_packet>` and the previous candidate inside `<previous_candidate>`, so writers read no `candidates/` or `feedback/` file). `<token>` is `run_next.writer_prompt_token(run, round, writer_no, cid)`, a 10-hex-char hash, the same device as `lineup.lineup_token`: post-writer's Read allow list can only be a run-wide glob, so the per-writer fence is the file name: a writer that knows its own number and cid still cannot construct a sibling's path and read that sibling's inlined packet and previous candidate. A `tier2/claims_<cid>.json` that exists before any action requested it is moved aside as `.unrequested` and re-requested. `state.json` caches derived state, `history` and `requested_outputs` (every output path an action asked for, with round, stage, ts and agent/tool). At deliver (and done) `run_next` moves the run's `round<k>/prompts/*.md` and `round<k>/writers/*.md` to `drafts/<run>/archive/round<k>/`, outside every agent's allow list. `run_next.py <run> --media <cid> --json` bypasses the stage machine: it emits the media-director (brief missing), `media_check.py` (check missing or older than the brief / prompts), the media-judge (judge file missing or older; prompt at `media/<cid>.judge.prompt.md`), then `aggregate.py merge` (the media part refreshed in `tier2/<cid>.tier2.json`) and `assemble_report.py`, writing `final/.stale` while anything is pending; its outputs are recorded in `state.json.requested_outputs` with stage `media` and the cached stage is left alone.

## 9. Lineup `drafts/<run>/tier2/lineup_<cid>.key.json`, `lineup_<token>.{prompt.md,<lens>.prompt.md,picks/<lens>.json}`, `lineup_<cid>.score.json`
`lineup.py build <cid> --seed N [--pool heldout|train]` (`run_next` and `health_run` ask for `train` while `common.small_corpus_mode` is on or the heldout split holds no post for the candidate's platform, `heldout` otherwise) → judge-facing files named by the opaque build token `lineup.lineup_token(run, cid, seed)` (sha256 prefix; the prompt names neither the cid nor another prompt file): posts A–D anonymized (URLs, @handles, emails, bare domains, every token of the filler author's name and handle, and the persona's own name / aliases / brands / handle stripped; every post escaped inside its tag), one prompt per lens with its own seeded order and a per-lens `nonce` the judge must echo. `lineup_<cid>.key.json` `{"candidate_slot":"C","fillers":[...],"seed":N,"token":"...","nonces":{lens: ...},"prompt_files":{...},"picks_dir":"...","orders":{"reader":[...],"voice":[...],"comedy":[...]}}` (never handed to judges). A rebuild wipes the picks directory. `lineup.py score <cid>` merges the picks the key names → `{"pass": bool, "picks":[{"lens","picked_candidate","confidence","tell"}], "invalid": [...], "rule":"..."}`; a pick without the matching nonce is invalid. Fail if ≥ 2 judges pick the candidate at confidence ≥ 4, or all 3 pick it.

## 10. Pairwise `drafts/<run>/tier2/pairwise_<cid>.{key.json,exemplars.key.json,score.json,exemplars.score.json}`, `pairwise_<token>.{<slot>.prompt.md,verdicts/<slot>.json}` and paraphrase
`pairwise.py build <cid> --mode reference|exemplars` → prompt files for both orders × lenses (reference) or one per exemplar, named by `pairwise.pairwise_token(run, cid, mode)` and carrying a per-slot `nonce`; headers name the platform, never the cid. `score` merges the verdicts the key names (a verdict without its nonce is invalid): inconsistent across orders = tie; `same_post_rewritten`/`same_skeleton_or_joke` true from any judge = `paraphrase: true`. Reference mode is advisory ranking; exemplar mode (vs the two closest `exemplars_seen`) is a hard gate. Exemplar ids in `style/exemplars.md` follow `[a-z][a-z0-9-]*_\d{3,}` (hyphenated slugs, 3+ digits).

## 11. Media brief `drafts/<run>/media/<cid>.brief.yaml`
Schema `postsmith.media/1`; the field list is `.claude/skills/media/references/brief_schema.md` §1. `media_check.py <brief> [--prompts dir]` validates schema, rule citation (M1–M7), aspect per platform, text budgets per tool (config), negation words absent in Veo/Runway/Nano Banana prompts, Veo/Runway caps, alt_text ≤ platform cap, no real-person names, brand check (exempt `real_capture_direction`), reject `genre: fake_screenshot` of a real product. Output `{"ok", "fails":[...], "warnings":[...]}`.

## 13. Memory and calibration records
`evals/calibration.jsonl`: `{ts, post_ref, kind: generated|corpus, platform, user_score, tags[], note, blind: bool, judge_scores{dim: median}, tier0_soft_flags[], lineup_pass, verdict, rubric_version, profile_version, moves[], lens, edit_ops[]}`. `corpus/ratings.jsonl`: `{post_id, user_score, tags, ts}`. ## 15. Hooks
`.claude/hooks/guard_paths.py --allow <glob>... --deny <glob>... [--bash-prefix <prefix>...]` reads the PreToolUse JSON on stdin (`tool_name`, `tool_input`, `cwd`), extracts the target path(s) (`file_path`, `path`, `pattern`, and for Bash a best-effort scan of tokens that look like paths), resolves relative to the payload `cwd` for Bash (following `cd <dir>` inside a command, expanding `$PWD` / `$CLAUDE_PROJECT_DIR` / `$POSTSMITH_ROOT` / `~`, reading a root-relative `/corpus/...` as the project path) and to `CLAUDE_PROJECT_DIR` otherwise, and exits 2 with a one-line reason when a deny glob matches (deny wins; a Grep/Glob search root, a Bash target that is a directory, or the literal prefix of a truncated glob expansion is blocked when a path-anchored deny glob could match below it) or, when `--allow` is given, when no allow glob matches (a Bash call whose cwd lies outside the project is then blocked). With `--bash-prefix` every Bash command segment must start with one of the prefixes. On a case-insensitive volume globs match case-insensitively. `guard_writes.py --allow <glob>... [--deny <glob>...]` does the same for Write/Edit targets. Both exit 0 otherwise. Policies are per agent: a Tier-1 judge reads only `round*/prompts/*.<lens>*.md` and the rubric and writes only `scores/*.<lens>*.json`; judge-persona also `tier2/claims_*.prompt.md` / `claims_*.json`; judge-lineup only `tier2/lineup_*.prompt.md` / `lineup_*.picks/*`; judge-pairwise only `tier2/pairwise_*.prompt.md` / `pairwise_*.verdicts/*`; media-judge only `media/*.judge.prompt.md` / `media/*.media-judge.json`; post-writer reads the brief, `round*/writers/*` and the style files and writes only `round*/candidates/r*-w*-*.md` (never `.txt`); profile-builder and post-annotator may run Bash only as `uv run tools/...`. `tools/tests/fixtures/hooks/agent_args/*.txt` mirror the agent front matter and a test pins them.

## 16. Module interfaces (so tier0.py can compose the check modules without CLI round-trips)
Each check module is importable from `tools/` (tier0 does `sys.path.insert(0, tools_dir)`) and exposes a pure function plus a CLI:
- `platform_check.run_checks(text: str, platform: str, meta: dict, cfg: dict) -> dict` → `{"checks": {check_id: result}, "chars": int, "x_len": int|None, "fold_preview": str, "advisory": {...}}` for P1_length, P2_fold, P_min_words, P3_hashtags, P4_links, P5_markup, P6_emoji. `meta` is the candidate front matter (may be `{}`); persona policy (hashtags/emoji/long posts) is read from `style/persona.md` front matter keys `platform_choices` when present, else config defaults.
- `stylometry.features(text: str, platform: str, lang: str = "en", lexicon: dict | None = None, patterns: dict | None = None) -> dict` (contract §3).
- `envelope_check.run_checks(features: dict, scope: str, profile: dict | None, cfg: dict, self_profile_scope: str | None = "self", small_corpus: bool = False) -> dict` → `{"checks": {"E1_envelope": ..., "P14_dashes": ..., "P15_burstiness": ..., "P16_broetry": ...}, "envelope": {...}}`; with `profile is None` every check is `{"class": "advisory", "pass": true, "note": "no profile"}`; with `small_corpus` (tier0 passes `common.small_corpus_mode(cfg)`) or a lens scope below `envelope.min_scope_n` the checks are widened / advisory as §5 says.
- `ai_tells.run_checks(text: str, platform: str, meta: dict, cfg: dict, lexicon: dict, patterns: dict, base_rates: dict | None) -> dict` → `{"checks": {...}}` for P7_bait, P8_opener, P9_residue, P10_contrast_flip, P11_cluster, P12_closer, P13_specifics, P17_lists, P18_hedges, P19_clickbait, P20_misc, plus `"hits": {"t1": [...], "t2": [...], "t3": [...], "claude": [...]}`. Base-rate downgrade is applied inside `ai_tells` only for ids in `cfg.base_rate_downgrade.applies_to`, recording `class_original` and `downgraded: true`.
- `overlap_check.run_checks(text: str, meta: dict, cfg: dict, lexicon: dict, corpus_index: dict, siblings: list[tuple[str, str]], published: list[tuple[str, str]], exclude_ids: set[str] = set()) -> dict` → O1_ngram, O2_phrases, O3_skeleton, O4_sibling, O5_published. `overlap_check.build_index(splits=("train","heldout","self"), include_cards=True, include_drafts_final=True, root=None, exclude_run=None) -> dict` builds the corpus index (normalized tokens, cards' archetype/hook_type/ending per post id, prior finalists: every `drafts/*/final/*.md` plus every other run's candidate whose merged.json says pass, at flag level; `exclude_run` names the current run). O2 fuzziness scales with phrase length (`overlap_check.phrase_tolerance`: exact below 8 normalized characters, then one edit per 8 up to `overlap.phrase_edit_distance`; numeric tokens must match exactly).
- `tier0.run(candidate_path: str, run: str | None = None, siblings: list[str] | None = None, exclude_ids: set[str] | None = None, lens_scope: str | None = None, as_golden=False, write=True, out_dir=None, root=None, cid=None) -> dict` → the §5 document; writes `<cid>.tier0.json` and `<cid>.txt` next to the candidate unless `--no-write`; the cid is `cid` or the file stem.
- `judge_io.validate(judge_json: dict, candidate_text: str, thresholds: dict, cfg: dict) -> dict` → `{"ok", "rejected": [{"dimension", "reason"}], "normalized": dict}`.
- `aggregate.merge(run: str, cid: str, round_k: int, tier0: dict, judge_files: list[dict], jury_files: list[dict], tier2: dict | None, previous_merged: dict | None, thresholds: dict, cfg: dict, profile: dict | None, waived: set[str]) -> dict` → §7 document. `aggregate.feedback(merged: dict, candidate_meta: dict) -> tuple[str, dict]` → (markdown, json).
- `matrix.assign(n: int, seed: int, moves: list[dict], scoreboard: dict, recent_runs: list[dict], lenses: list[str], persona: dict, taxonomies: dict) -> list[dict]` (assignments per §4 `assignment`), with the fallback ladder and `rung` recorded.
- `lineup.build(cid, run, seed, pool) / lineup.score(cid, run)`; `pairwise.build(cid, run, mode) / pairwise.score(cid, run, mode)`; `media_check.check(brief: dict, prompts: dict[str, str], cfg: dict, platform: str) -> dict`.
- Hooks read stdin JSON: `{"tool_name": "Read", "tool_input": {"file_path": "..."}, "cwd": "..."}` (also `Grep`: `pattern`,`path`; `Glob`: `pattern`,`path`; `Bash`: `command`; `Write`/`Edit`: `file_path`).
- `common.escape_untrusted(text)` neutralises every wrapper tag (`untrusted_post`, `untrusted_claims`, `fold_preview`, `reference_post`, `self_post`, `media_brief`, `tool_prompt`, `persona_excerpt`, `brief_facts`, opening and closing, fullwidth slash included) and is used by every prompt builder; `common.check_needs_action(res)` is the one rule for "failed or flagged"; `common.small_corpus_mode(cfg, root=None)` is the one small-corpus rule; `common.x_segments` / `x_count` / `x_cut_index` share X counting; `lineup.lineup_token`, `pairwise.pairwise_token`, `lineup.build_nonce` name the Tier 2 files.

## 17. Remaining tool CLIs (skills reference these exact names and flags)
- `ingest_normalize.py <source> [--kind csv|json|md|auto] [--author X] [--platform linkedin|x] [--self] [--mapping '{...}'] [--json]` → writes `corpus/inbox/normalized_<sha>.jsonl` (rows: `{author_name, author_slug, platform, text, posted_at, url, engagement, media: [{path_or_url, description}], transcript, source_ref}`) and prints `{"ok", "rows", "unmapped_columns", "needs": ["platform"|"author"|...], "file"}`. When `needs` is non-empty the skill asks the user and re-runs with `--platform`/`--author`/`--mapping`.
- `ingest_commit.py <normalized.jsonl> [--self] [--consent-media] [--json]` → dedupe against `corpus/manifest.jsonl`, assign sticky split (or small-corpus mode), create post files, copy local media, list remote media URLs it did not fetch (unless `--consent-media`), move the source file to `corpus/inbox/done/`; prints `{"ok", "ingested": [ids], "skipped": [...], "variants": [...], "crossposts": [...], "remote_media": [...], "small_corpus_mode": bool, "heldout_counts": {...}}`.
- `media_prepare.py [--post id] [--all] [--json]` → previews, frames, contact sheets, audio (only if a stream exists), transcript hookup; updates the post file's `media` entries; prints per-post results.
- `card_lint.py [--post id] [--all] [--json]` → per contract §2; prints `{"ok", "problems": [{"post_id", "field", "problem"}]}`.
- `moves_lint.py [--json]` → `{"ok", "problems": [...], "moves": n}`.
- `assemble_report.py <run> [--copy] [--json]` → writes `final/` (`<cid>.md`, `clipboard.md`, `report.md`, `lineage.json`, the blind set of §18) from merged scores, tier2 files and media briefs; verdict labels only from merged.json; `--hide-verdicts` (default when no blind rating row exists for the run) writes `report.md` with verdicts in a collapsed "after blind rating" section; prints the terminal layout to stdout.
- `health_run.py [--scope deterministic|judges|all] [--rubric vN] [--write] [--json]` → runs golden negatives/positives/oracle/lineup-controls/drift/judge-sanity task lists; for judge items it emits the list of judge actions (like run_next) into `drafts/eval_<date>/` and a second invocation `--collect` scores them; writes `evals/health/reports/<date>_<rubric-sha>_<profile>.md`; prints `{"ok", "green": bool, "sections": {...}}`.
- `calibrate.py [--json]` → κ, ρ, per-tag false negatives, proposals; refuses κ until config `calibration.min_system_fails_for_kappa` system-fail ratings exist; writes `evals/health/reports/calibration_<date>.md`.
- `rate_record.py --kind generated|corpus --ref <post_ref|post_id> --score N [--tags a,b] [--note ...] [--blind] [--json]` → appends calibration/ratings rows joined with judge scores; `--proposals` prints lexicon/anchor/threshold proposals when due.
- `posted_record.py <run> <cid> [--url U] [--text-file F] [--metrics "12k views 40 comments"] [--json]` → memory/published + performance rows, `edit_ops` diff.
- `lessons.py add|consolidate|retire [--json]`, `topics.py add|scoreboard [--json]` (small helpers used by /rate and /post).
- `judge_sanity.py <hook.log> [--agents a,b] [--json]` → `{"ok", "green", "calls", "problems": [{call, problem, rows}], "per_call": {...}}`: the judge-sanity assertion over a `POSTSMITH_HOOK_LOG` file (one prompt read per judge call, only the rubric otherwise, zero blocked decisions); `health_run.py` calls it.

## 18. Annotation prompt files, writer prompt paths, blind rating, media rebuild
- **Heldout isolation for annotation.** `.claude/settings.json` denies `Read(corpus/heldout/**)` session-wide, so no agent reads a heldout post directly. Instead `card_prompts.py build [--post id | --all-uncarded] [--kind annotate|verify]` writes self-contained prompt files under `drafts/learn_<date>/prompts/<post_id>.annotate.md` (post text inside `<untrusted_post>` via `common.escape_untrusted`, `media` entries with preview / contact-sheet paths under `corpus/media` and `corpus/frames` which are NOT denied, the card spec pointer, the output path `corpus/cards/<id>.md` or `corpus/heldout/cards/<id>.md`) and `<post_id>.verify.md` (post text + the card text inline + output path `corpus/cards/_reviews/<id>.md` or `corpus/heldout/cards/_reviews/<id>.md`). `post-annotator` and `card-verifier` receive only the prompt file path and the output path; their Read hooks allow `drafts/learn_*/prompts/*`, `corpus/media/**`, `corpus/frames/**`, `style/taxonomies/**`, `.claude/skills/learn/references/*` and deny everything else under `corpus/` and `drafts/`. Learn prompt files are archived under `drafts/learn_<date>/archive/` when `/ingest` finishes (quote_leak_check ignores `drafts/learn_*`).
- **Writer prompt paths** are `drafts/<run>/round<k>/writers/writer-<n>.<token>.md` and `writers/rewrite-<cid>.<token>.md` (packet + previous candidate inlined; `<token>` = `run_next.writer_prompt_token`). Skills and references must use these names, and must pass an action's `prompt_file` through rather than reconstructing it.
- **Judge voice prompt** inlines the assigned move's `style/moves.md` entry (mechanism, trigger, shape, execute_without_copying; never `seen_in`) as `<move_entry>`; `level_and_move` is `na` only when the prompt says `lens: none`.
- **Tier 2 judge-facing files** are token-named (`tier2/lineup_<token>.<lens>.prompt.md` → `lineup_<token>.picks/<lens>.json`; `tier2/pairwise_<token>.<slot>.prompt.md` → `pairwise_<token>.verdicts/<slot>.json`) with per-slot nonces; cid-named key/score files are never handed to judges. Skills read paths from `run_next` actions.
- **Blind rating.** `assemble_report.py <run>` writes `final/blind.json` (`{"run", "items": [{"key": "A"|"B"|"C", "platform", "text"}], "seed"}`, seed-shuffled from the finalist, an alternate and a did-not-pass candidate when available, verdict-free) and, by default, `report.md` with verdict labels collapsed under "After blind rating" until a calibration row with `blind: true` exists for the run (`--show-verdicts` forces them). `rate_record.py --blind --ref <run>:<key>` maps the key back through `final/blind.json`. `rate_record.py --list-rated --kind corpus|generated --json` → `{"ok", "ids"}`.
- **Media rebuild.** `run_next.py <run> --media <cid> --json` re-derives only the media step for a delivered run (media-director action, media_check tool action, media-judge action) and marks `final/` stale so `assemble_report.py` is re-run.
- **Topics.** `topics.py add <run> [--outcome pass|posted|skipped] [--json]` upserts the run's row; `topics.py scoreboard --json` rewrites the moves scoreboard from `evals/calibration.jsonl`; `topics.py proven --json` rewrites `## Proven angles` from `memory/performance.jsonl`.
- **Persona front matter keys** the tools read: `platform_choices` (see platform_check), `can_claim`, `cannot_claim`, `do_not_target`, `name`, `brands`, `aliases`, `handle`, `updated`.
